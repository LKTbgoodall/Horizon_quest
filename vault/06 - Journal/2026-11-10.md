## 🧠 Learned / discovered
- **Horizon is not a modloader**: it is Minecraft 26.3 rewritten in Rust. Mods are **native Rust**, compiled into the game → [[Horizon - Overview]].
- The `smp` mod proves that a **server mod with a GUI through chest menus**, commands and JSON saving works with vanilla clients → [[Example - smp mod (patterns to reuse)]].
- Most useful events exist: `mob_killed`, `item_crafted`, `advancement_done`, `changed_dimension`, `item_picked_up`, `stat_award`… However, the ideal hook for items (`player_inventory_changed`), toasts and titles are still ⏳ → [[Horizon hooks and API]].
- A **custom client screen** is possible (`native_mod_screen_open` + rendering + input), but there is **no widget library**: everything has to be done by hand.
- Commands with `--trust-native-code` must be run by the user, **never by an agent**.
- FTB Quests is licensed *All Rights Reserved*: we reimplement the concepts, we copy nothing.

- The game is built with `-D warnings`, so a pure module that no glue calls yet is **dead code there** (smp marks such items `#[allow(dead_code)]`). Rule: a pure module enters `horizon-mixin.toml` together with the glue that uses it.
- A bundle's `data/` folder may hold any files; they are compiled in with `native_data!("horizon_quests", "quests/…")` and are **not** beside the game at run time.
- The dev PC has no Python: use the edit tools or shell for file changes.
- An unused `pub fn` in a module of the bundle is dead code in the game too (smp marks them `#[allow(dead_code)]`), so nothing may be added to `hq_canvas.rs` (in the bundle) before the glue calls it: the real book went into a new module, `hq_book.rs`.
