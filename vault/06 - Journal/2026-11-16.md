# 2026-11-16

## The mod API lands upstream: PR 16007 closed, our format refused on `main`
- Bastien pasted the close of horizon-rust/horizon#16007 (the fix for horizon#15933, our combined `.hmod` losing its content): its author closed it as **superseded by horizon-rust/horizon#17145**, which rewrote the launcher's native mod handling. A mod is now **one flat package** (`horizon-mod.toml` with `[native]`), and the `horizon-native.json` / `horizon-mixin.toml` / `mixins/<id>/` layout is **refused outright**, so #15933 no longer applies on `main` (the issue itself is still open).
- Checked on GitHub and in `ext/horizon` (fetched `origin/main` at `90e97a1`):
  - PR #17145 "The mod API: #16941 merged with main" was **merged 2026-11-16 01:32 UTC** (merge `85b5bcca7c`). It is the arismoko fork's API ([[Fork - arismoko mod API]]).
  - **Not released yet**: the newest launcher, 0.2.69 (`4626921`, published 00:57 UTC), was built **before** the merge; the Nightly is still `9f42064`. So today's players and Bastien's builds still take our current format. The first Nightly and launcher built from the new `main` will refuse it.
  - The new format, the SDK build and the tools are written up in [[Native mods - structure and manifest]] § "The new format".
- What it means for us:
  - **Good**: content and code ship in one `.hmod` natively; the textures problem that held 1.0.0 goes away **with the new format**. Crates from crates.io are allowed (with a lock). The game is not rebuilt, so builds should be much faster.
  - **Cost**: our mod is written against the old `native_*` hook points (32 targets in `horizon-mixin.toml`, 43 `native_*` helpers in the glue), which no longer exist for mods. The pure modules (`hq_*.rs`) move as they are; the glue and the hook files must be rewritten against `mod_api::Hooks` / `ServerHost` / `ClientHost`, `native_data!` replaced by `data/` + reload listeners or generated source.
- A subagent mapped every hook and helper we use to the new API (read in `crates/horizon-mod-vocab/src/` and the book at `90e97a1`): nearly all exist under the same name without `native_`; real gaps are `native_data!`, `native_take_items` / `native_carried_items`, `native_recipes`, free-text client settings (our tracked quest) and `native_corner_shown`; channels, key mappings, commands and reload listeners change shape; `WorldOpenReady` became `server_started`. Details and options in [[ADR-018 Port to the mod API]] (proposed, waiting for Bastien). Event field names and some handle methods were inferred from rustdoc, not read in the generated structs: the port's first compile is the real check.
- Nothing can be compiled against the new API yet: no Nightly (and so no SDK) has been built from the new `main`.

## The port, done on a branch (evening)
- Bastien: "can't you take care of porting it in the meantime?" Yes, and not blind: a mod's `Cargo.toml` takes the API crate by path from `.horizon/sdk/api/`, so a junction from there to a Horizon checkout (`ext/horizon`, cloned again on this PC: `main` at `c07bfa7`) lets `cargo check` / `cargo test` compile the mod against the real API. A smoke mod from the template checked in 1.5 min and its tests linked.
- Branch **`mod-api-port`** (pushed; `main` keeps the old format for the current release):
  - `mod/` is the flat package: `horizon-mod.toml` (`side = "both"`, `[native]` pinned on `main` `c07bfa7` and horizon-mixins `5a64af9` until a Nightly), `Cargo.toml` (`horizon-mod-api` by path, `serde`, `serde_json`, `toml`, `log`), `src/` (the `hq_*` modules moved as they are), `assets/` (from the old content half), `data/horizon_quests/horizon/item/quest_book.json` (the Quest Book, the old `native_items`).
  - `src/lib.rs`: one `#[mod_api::horizon_mod] impl Hooks` routing 30 hooks to the two glue files, plus the channel's two `IPayloadHandler`s. The glue keeps its shape; details of every mapping in [[Horizon hooks and API]] (new box at the top).
  - Differences: the open key is a `KeyRegistration` on Options > Controls (label from `lang`), read with `consume_click`; the tracked quest goes to `horizon-mod-data/horizon_quests/tracked.txt` (a setting would show on Options > Mods); every player is a `PlayerRef`, so the host / guest paths merged (hand-in by `inventory_slots` + `/clear`, place by `dimension` + `entity().position`, may-edit by `permission_level`); `give_stack` drops what does not fit itself; a missed level is read from `experience()` instead of probing with commands; `native_corner_shown` has no equivalent (the HUD always draws).
  - `native_data!` is gone and a package carries Rust only under `src/`: the example pack moved to `mod/built-in-pack/` and is compiled in as `src/hq_built_in.rs`, generated by `tools/gen-built-in-pack.py` (a test fails when it is stale; line endings normalised because of `core.autocrlf`). The integration tests moved into `src/tests/` (a `.rs` outside `src/` refuses the package), the book preview to `tools/book-preview/` (its own crate).
  - Tools: `link-sdk.ps1/.sh`, `check-mod.ps1/.sh` (replace `check-glue`), `build-mod.ps1/.sh` now just `native-build mod --instance ... --trust-native-code` (needs the new launcher).
- Result: **`cargo test`: 244 passed, no warning with `-D warnings`**; `cargo check --lib` clean; the preview crate checks.
- **The registry's package check accepts it**: `cargo horizon-mod check <file>` (the tool built from `ext/horizon`) on a zip of the package's files says `horizon_quests 0.20.0 (native-mod, format native-1/c07bfa7.../5a64af9..., for 26.3)`, unsigned, source not executed.
- Pitfall: `cargo horizon-mod check` run **in the project** (no file) tries to fetch the pinned build's SDK, finds none (404 for `sdk-c07bfa7...`) and leaves `mod/.horizon/sdk/` empty: the junction is gone (the checkout it pointed to is untouched). Run `tools/link-sdk.ps1` again.
- Not checked, needs the Nightly and the game: everything at run time (the channel in single player, `run_mod_command` actually reaching us, the reload listener, the item file, the key on Controls, `data_files`, the HUD corners), the registry lock (`native-lock`), and whether the package passes the launcher's checks.
- Pitfalls: a heredoc with `!` and quotes broke under the Bash tool; a Python heredoc turned `\r\n` into real line breaks. Write such scripts to a file first.
