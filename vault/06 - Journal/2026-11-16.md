# 2026-11-16

## The mod API lands upstream: PR 16007 closed, our format refused on `main`
- Bastien pasted the close of horizon-rust/horizon#16007 (the fix for horizon#15933, our combined `.hmod` losing its content): its author closed it as **superseded by horizon-rust/horizon#17145**, which rewrote the launcher's native mod handling. A mod is now **one flat package** (`horizon-mod.toml` with `[native]`), and the `horizon-native.json` / `horizon-mixin.toml` / `mixins/<id>/` layout is **refused outright**, so #15933 no longer applies on `main` (the issue itself is still open).
- Checked on GitHub and in `ext/horizon` (fetched `origin/main` at `90e97a1`):
  - PR #17145 "The mod API: #16941 merged with main" was **merged 2026-11-16 01:32 UTC** (merge `85b5bcca7c`). It is the arismoko fork's API ([[Fork - arismoko mod API]]).
  - **Not released yet**: the newest launcher, 0.2.69 (`4626921`, published 00:57 UTC), was built **before** the merge; the Nightly is still `9f42064`. So today's players and Bastien's builds still take our current format. The first Nightly and launcher built from the new `main` will refuse it.
  - The new format, the SDK build and the tools are written up in [[Native mods - structure and manifest]] § "The new format".
- What it means for us:
  - **Good**: content and code ship in one `.hmod` natively; the textures problem that held 1.0.0 goes away **with the new format**. Crates from crates.io are allowed (with a lock). The game is not rebuilt, so builds should be much faster.
  - **Cost**: our mod is written against the old `native_*` hook points (32 targets in `horizon-mixin.toml`, 43 `native_*` helpers in the glue), which no longer exist for mods. The pure modules (`hq_*.rs`) move as they are; the glue and the hook files must be rewritten against `mod_api::Hooks` / `ServerHost` / `ClientHost`, `native_data!` replaced by `data/` + reload listeners or generated source.
- A subagent mapped every hook and helper we use to the new API (read in `crates/horizon-mod-vocab/src/` and the book at `90e97a1`): nearly all exist under the same name without `native_`; real gaps are `native_data!`, `native_take_items` / `native_carried_items`, `native_recipes`, free-text client settings (our tracked quest) and `native_corner_shown`; channels, key mappings, commands and reload listeners change shape; `WorldOpenReady` became `server_started`. Details and options in [[ADR-018 Port to the mod API]] (proposed, waiting for Bastien). Event field names and some handle methods were inferred from rustdoc, not read in the generated structs: the port's first compile is the real check.
- Nothing can be compiled against the new API yet: no Nightly (and so no SDK) has been built from the new `main`.

## Decisions
- Proposed [[ADR-018 Port to the mod API]]: port when the first mod API Nightly and its SDK are out, and make 1.0.0 the first version on it. Waiting for Bastien.
